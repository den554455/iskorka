# Ручная проверка навыка в Яндекс Диалогах (хостинг — Amvera Cloud)

Цель: развернуть backend на Amvera, получить HTTPS-адрес, подключить его к черновику навыка и пройти серию голосом и текстом в консоли Диалогов.

**Что проверено, а что нет.** Команда запуска, путь к БД и секретный адрес проверены локально. Шаги Amvera взяты из их документации (источники внизу). Сам деплой на Amvera и работа с Диалогами **не запускались** — это первая реальная проверка. Места, где документация не подтверждена, помечены «⚠ уточнить».

Перед началом: локально `python -m pytest -q` должен показать `124 passed`.

---

## Шаг 0. Подготовьте секреты

Понадобятся два значения (сгенерируйте в PowerShell, сохраните в надёжном месте):

```powershell
python -c "import secrets; print(secrets.token_hex(32))"   # → PLAYER_KEY_PEPPER
python -c "import secrets; print(secrets.token_hex(16))"   # → WEBHOOK_SECRET
```

- `PLAYER_KEY_PEPPER` после запуска **не менять**: все профили игроков привязаны к нему.
- `WEBHOOK_SECRET` попадёт в адрес `https://…/alice/<секрет>`. Это единственная защита от посторонних запросов.

## Шаг 1. Создайте проект на Amvera

1. Войдите на [cloud.amvera.ru](https://cloud.amvera.ru), нажмите **«Создать проект»**.
2. Тип сервиса — **«Приложение»**. Укажите название (например, `iskorka`), тарифный план, **«Далее»**. Дождитесь окончания загрузки: откроется этап «Загрузка данных».

## Шаг 2. Переменные окружения

На этапе создания есть необязательный шаг переменных окружения (так сказано в документации Amvera). Задайте:

| Переменная | Значение |
|------------|----------|
| `PLAYER_KEY_PEPPER` | значение из шага 0 |
| `WEBHOOK_SECRET` | значение из шага 0 |
| `DATABASE_URL` | `sqlite:////data/iskorka.db` (четыре слэша подряд) |
| `LOG_LEVEL` | `INFO` |

**Важно про `DATABASE_URL`.** Постоянное хранилище Amvera смонтировано в `/data` (так в документации). Всё вне `/data` стирается при пересборке. Если оставить значение по умолчанию (`./data/…`), прогресс игроков будет пропадать при каждом обновлении.

⚠ уточнить: как называется раздел переменных в настройках уже созданного проекта и нужен ли перезапуск после их изменения — страница документации не открылась. Секреты не кладите в код и в файл `.env` (в архив он не входит).

## Шаг 3. Загрузите код

В архиве уже есть `amvera.yml`:

```yaml
meta:
  environment: python
  toolchain:
    name: pip
    version: "3.13"
build:
  requirementsPath: requirements.txt
run:
  command: uvicorn --host 0.0.0.0 --port 80 --factory app.main:create_app
  containerPort: 80
  persistenceMount: /data
```

**Вариант А — через интерфейс.** Перетащите в окно загрузки содержимое папки проекта: `app/`, `amvera.yml`, `requirements.txt` (можно и остальное). **Не загружайте** `.venv/`, `data/`, `.env`. Проверьте список загруженных файлов и нажмите **«Завершить»** — начнутся сборка и запуск.

**Вариант Б — через git:**

```powershell
git clone https://git.amvera.ru/<ваш_логин>/<slug_проекта>
# скопируйте в созданную папку файлы проекта (без .venv, data, .env)
cd <slug_проекта>
git add .
git commit -m "Искорка: первая серия"
git push origin master
```

После `push` проект собирается и разворачивается автоматически (ветка именно `master`).

Следите за разделами **«Сборка»** и **«Запуск»** проекта: сборка должна завершиться, а в логах запуска не должно быть ошибок. Если в логах есть `Сценарий некорректен` — сценарий не прошёл проверку и приложение намеренно не стартует.

## Шаг 4. Домен и HTTPS

1. Откройте вкладку **«Домены»** проекта → **«Добавить доменное имя»**.
2. Тип подключения — **HTTPS**, тип домена — **«Бесплатный домен Амвера»**.
3. Подождите: создание ingress и выпуск сертификата занимают время. Ошибки SSL часто связаны с кэшем браузера — подождите минут 10 или откройте в другом браузере.

Адрес будет вида `https://<проект>-<логин>.<регион>.amvera.tech` (точный вид покажет вкладка «Домены»).

Порты настраивать отдельно не нужно: Amvera принимает HTTPS на своей стороне и передаёт запрос в приложение на порт 80 (`containerPort`).

**Проверка живости.** В браузере откройте `https://<ваш-домен>/health` → должно быть `{"status":"ok"}`. Затем `https://<ваш-домен>/alice/<WEBHOOK_SECRET>` в браузере вернёт `405 Method Not Allowed` — это нормально: адрес принимает только POST.

**Проверка диалога с вашего компьютера** (проверяет весь путь: домен, HTTPS, секрет, БД):

```powershell
python -m scripts.dev_test --url https://<ваш-домен>/alice/<WEBHOOK_SECRET> --player amvera-check --say "|да|да|ыыы|в саду"
```

Ожидаемо: приветствие Искорки, находка семечка, вопрос «послушаем?», переспрос, финал серии. Профиль `amvera-check` останется в базе на сервере: `--reset` работает только с локальной БД. Это безвредно, но если нужно начать заново, используйте другое имя после `--player`.

⚠ уточнить: Amvera пишет, что на домене работает базовая защита (WAF) и «подозрительные запросы могут получить `{"error": "forbidden"}`». Запросы Яндекса к вам должны проходить, но если в консоли Диалогов будет «навык не отвечает», а ваш `dev_test` работает, — проверьте мониторинг входящего трафика во вкладке «Мониторинг» и поддержку Amvera.

## Шаг 5. Подключите навык в Яндекс Диалогах

1. Откройте [консоль разработчика](https://dialogs.yandex.ru/developer/) и создайте навык (тип — навык в Алисе). ⚠ уточнить: точные названия кнопок создания в интерфейсе мы не проверяли.
2. Вкладка **«Настройки»** → блок **Backend** → поле **Webhook URL**: `https://<ваш-домен>/alice/<WEBHOOK_SECRET>` → **«Сохранить»** внизу страницы.
3. Название навыка пока любое рабочее (для приватного/черновика проверяются активационное имя и иконка). Для публикации нужно 2–5 слов, например «Искорка и Долина чудес» (раздел 3.1 ТЗ).
4. Опцию «Использовать хранилище данных в навыке» **не включайте**: прогресс хранится у нас.

## Шаг 6. Ручная проверка во вкладке «Тестирование»

Откройте вкладку **«Тестирование»** (согласно документации Яндекса, при правильной настройке сразу появляется приветствие). Пройдите чек-лист и отмечайте результат:

| № | Действие (что вводить) | Ожидаемый результат | Ок? |
|---|------------------------|---------------------|-----|
| 1 | Открыть вкладку | Приветствие Искорки, вопрос «Поможешь? Скажи «да»» | |
| 2 | `да` | Находка семечка, знакомство с Тишей, вопрос «послушаем?» | |
| 3 | `да` | Семечко «поёт», вопрос «сад или ручей?» | |
| 4 | `динозавр` | Мягкий переспрос, без ошибки | |
| 5 | `подскажи` | Подсказка про «сад» / «ручей» | |
| 6 | `давай в садик` | Цветок в саду, финал, сессия закрылась | |
| 7 | Запустить навык заново | «С возвращением», в саду сияет цветок; вопрос «послушать ещё раз?» | |
| 8 | `помощь` | Правила и вернулся тот же вопрос | |
| 9 | `что ты умеешь` | Рассказ о навыке, вопрос повторён | |
| 10 | `хватит` | Прощание, сессия закрыта | |
| 11 | Новый запуск после выхода | Прогресс сохранён | |
| 12 | Нажать кнопку «Да»/«Нет»/«В саду» | Работает как сказанная фраза | |
| 13 | Повторить с вариантами: «возле воды», «у ручья» | Выбор ручья засчитан | |

**Проверка сохранения между запусками.** Прогресс привязан к `application_id` приложения. Перезапуск навыка в той же консоли должен вернуть прогресс. ⚠ уточнить: одинаков ли идентификатор между сессиями в консоли тестирования — это допущение 3.3.3 из ТЗ; если при втором запуске Искорка здоровается заново, зафиксируйте это — значит, идентификатор меняется.

**Что записать по итогам** (это закрывает «непроверенное» из раздела 10 ТЗ):
- пришёл ли `application_id` и стабилен ли он между запусками;
- время ответа (должно быть заметно меньше 4,5 секунд);
- повторные запросы: в логах Amvera (раздел «Запуск») ищите строки «Повторный запрос: возвращён сохранённый ответ»;
- как Алиса озвучивает текст (ударения, паузы) — на реальной колонке или в приложении.

## Шаг 7. Если что-то не работает

| Симптом | Что проверить |
|---------|---------------|
| «Навык не отвечает» | `/health` открывается? Webhook URL с секретом и без опечаток? Сертификат выпущен? Приложение запущено (раздел «Запуск»)? |
| 404 в логах входящих запросов | В Webhook URL нет `/alice/<секрет>` или секрет не совпадает с `WEBHOOK_SECRET` |
| Прогресс пропадает после обновления кода | `DATABASE_URL` не указывает в `/data` |
| Приложение не стартует, `Сценарий некорректен` | Ошибка в `episodes.json`; запустите локально `pytest` |
| Ответ с текстом «у Искорки запутались лапки» | Внутренняя ошибка; подробности — в логах запуска (там только тип исключения, без реплик и идентификаторов) |
| SSL-ошибка в браузере | Подождите ~10 минут, очистите кэш; домен в нижнем регистре |

## Ограничения этой схемы

- Приложение работает в одном экземпляре: защита от гонок построена на замке в процессе. Не запускайте несколько реплик.
- SQLite в `/data` подходит для проверки и небольшой нагрузки. Резервные копии БД и условия хранения на Amvera не изучали ⚠ уточнить.
- Входящий трафик на Amvera тарифицируется, есть бесплатный лимит и ограничения (размер запроса, таймаут, число запросов в минуту) — для ручной проверки хватит, для запуска проверьте тариф.
- До публикации навыка пройдите чек-лист раздела 10 в `TECHNICAL_SPEC.md`.
