# Искорка — голосовой навык для Яндекс Алисы (месяц контента: 30 эпизодов)

Детский голосовой сериал (4–8 лет): ребёнок помогает лисёнку Искорке зажечь пять ветвей Великого дерева. В проекте **30 эпизодов** (5 арок, 15 серий по 2 эпизода): один эпизод — один визит. Выборы ребёнка (сад или ручей, имя светлячка, подарок мосту и т. д.) сохраняются и возвращаются в поздних эпизодах; в эпизоде 30 звучит пересказ «нашей истории» по его решениям.

План месяца, правила написания и карта эпизодов: [SPEC_STORY.md](SPEC_STORY.md). Что исправлено при проверке: [REVIEW_FIXES.md](REVIEW_FIXES.md).

Запуск на Amvera и ручная проверка в Диалогах: [DEPLOY_AMVERA.md](DEPLOY_AMVERA.md).

Подробности, требования платформы и границы проверки — в [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md).

> **Статус.** Код и тесты проверены на Linux (Python 3.13): **947 тестов проходят, 13 пропущены осознанно**, сервер отвечает по HTTP; все 30 эпизодов проходятся по кнопкам в тестах. На **Windows, на Amvera и в реальных Яндекс Диалогах не проверялось.** Звуковых эффектов пока нет: пометки `[звук: …]` в текстах перед отправкой вырезаются (иначе Алиса читала бы их вслух). Длительность: эпизод 1 по вашему замеру 3,6 минуты; остальные эпизоды короче по объёму текста (1400–2250 знаков на счастливом пути), их время не мерили.

## 1. Требования

- Python 3.12 или новее (проверено на 3.13). Docker, Redis и облачные сервисы не нужны.
- Интернет — только для установки пакетов. Офлайн: на машине с интернетом выполните `pip download -r requirements.txt -d wheels`, перенесите папку `wheels` и установите `pip install --no-index --find-links wheels -r requirements.txt`.

## 2. Установка (Windows, PowerShell)

```powershell
cd путь\к\iskorka
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если PowerShell запрещает запуск скриптов:
`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`, затем снова `Activate.ps1`.

Откройте `.env` и впишите значение `PLAYER_KEY_PEPPER`. Сгенерировать:

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

Не меняйте это значение после запуска: профили игроков привязаны к нему.

## 3. Запуск тестов

```powershell
python -m pytest -q
```

Ожидаемый результат: `947 passed, 13 skipped` (около 40 секунд). Пропуски нормальны: в 6 эпизодах (3, 11, 15, 17, 25, 29) нет записываемого решения, и в загадке эпизода 1 на кнопках только подсказки. Тесты используют временные базы и ваши данные не трогают.

## 4. Запуск сервера

```powershell
python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

Проверка: откройте в браузере `http://127.0.0.1:8000/health` — увидите `{"status":"ok"}`.

SQLite-файл создаётся автоматически: `data\iskorka.db` в папке проекта (путь меняется через `DATABASE_URL`).

## 5. Локальный диалог

Во втором окне PowerShell (с активированным окружением):

```powershell
# Интерактивно по HTTP, как это делали бы Диалоги. Пустая строка = запуск навыка.
python -m scripts.dev_test --url http://127.0.0.1:8000/alice

# Без сервера, напрямую через игровой сервис и БД
python -m scripts.dev_test --local
```

**Проверить конкретный переход** (реплики через `|`, первая пустая — запуск):

```powershell
python -m scripts.dev_test --local --say "|да|да|дерево|динозавр|в саду"
python -m scripts.dev_test --local --say "|помощь|хватит"
```

**Сбросить тестового игрока:**

```powershell
python -m scripts.dev_test --reset --player dev-player
```

Полный сброс — остановить сервер и удалить `data\iskorka.db`:

```powershell
Remove-Item -Recurse -Force data
```

Что говорить в игре: «да», «нет», «в саду», «давай в садик», «у ручья», «возле воды», «подскажи», «повтори», «помощь», «что ты умеешь», «хватит».

## 6. Подключение к Яндекс Диалогам

Делайте это только после того, как локальные тесты проходят.

1. **Публичный HTTPS-адрес.** Диалоги ходят на ваш сервер по HTTPS, `localhost` не подходит. Нужен сервер с доменом и сертификатом (или туннель на время тестов; выбор хостинга за вами). В документации Яндекса сказано, что сертификат импортируется на сервер, но какие требования к нему предъявляются, на проверенной странице не указано — уточните в документации.
2. Задайте в `.env` `WEBHOOK_SECRET` (например, случайная строка): тогда адрес станет `https://ваш-домен/alice/<секрет>`. Это единственная защита от посторонних запросов в MVP.
3. В [консоли разработчика](https://dialogs.yandex.ru/developer/) создайте навык, откройте «Настройки», в блоке **Backend** в поле **Webhook URL** укажите адрес из п. 2, сохраните.
4. Вкладка **«Тестирование»** — должно появиться приветствие Искорки. Пройдите серию целиком, проверьте «Помощь» и «Что ты умеешь».
5. Параметры, которые нужно получить и подготовить в кабинете: идентификатор навыка (`skill_id`, на вкладке «Общие сведения»), название (2–5 слов — «Искорка» одним словом не пройдёт, если это не подтверждённый бренд), активационные имена, описание с контактами разработчика, иконка, категория и возрастные настройки.
6. Опцию «Использовать хранилище данных в навыке» включать **не нужно**: прогресс хранится в нашей БД.
7. Публикацию и модерацию не начинайте, пока не пройдёте чек-лист из раздела 10 в TECHNICAL_SPEC.md.

Что приходит от платформы, логируется без идентификаторов и реплик. Для отладки повторов запросов временно включите свой лог с `session_id` и `message_id` на тестовом навыке.

## 7. Как это устроено (кратко)

- `app/game/` — движок и распознавание, не зависят от Алисы и БД.
- `app/content/episodes/ep1.json … ep30.json` — сценарий, по файлу на эпизод; `series.json` — порядок серий и арок; `world.json` — реестр ключей решений и предметов мира. При запуске всё проверяется (`app/content/validation.py`); некорректный сценарий не даёт приложению стартовать.
- `app/game/engine.py` — `Engine` на один эпизод и `MultiEngine` с переходом «Ещё» между эпизодами.
- `app/db/`, `app/service.py` — SQLite, один ход = одна транзакция, защита от повторов.
- `app/api/alice_webhook.py`, `app/schemas/alice.py` — адаптер Диалогов.

**Правка текста:** изменяйте варианты в `app/content/episodes/epN.json`, затем `python -m pytest -q`. Тесты проверят ссылки между узлами, достижимость, завершение, циклы, лимиты длины (1024 символа), обращения без рода и то, что все кнопки понимаются.

**Новый выбор или слово-ответ.** Новый ключ решения объявите в `world.json` (значения и `default`), слова-ответы добавьте в `app/game/intents.py` (`_EXTRA_WORDS`: формы без «ё»). Иначе валидатор или тест кнопок покажет ошибку.

**Тесты (12 файлов):** `test_game_engine`, `test_intents`, `test_progression`, `test_alice_webhook`, `test_content` — базовые; `test_episodes_flow` — переход эпизод 1 → 2 и лимит визита; `test_all_episodes` — проход всех 30 эпизодов по кнопкам; `test_content_all`, `test_intents_words`, `test_regressions`, `test_month` — структура месяца, кнопки и поведение движка в каждом эпизоде; `test_migration` — миграция старой базы.

## 8. Известные ограничения

- Длительность: замерен только эпизод 1 (3,6 мин). Остальные эпизоды короче по знакам, реальное время нужно замерить на устройстве.
- Звуковых эффектов нет (колокольчик, ручей и др. запланированы): пометки `[звук: …]` вырезаются перед отправкой.
- Не более 2 эпизодов за один визит: затем Искорка мягко прощается, следующий эпизод ждёт в новом визите.
- Просьба «добавить немного похвалы» (SPEC_STORY, вопрос 9) пока не выполнена.
- Профиль привязан к приложению/устройству (`application_id`), а не к аккаунту.
- Нет миграций БД; один процесс.
- Нет `tts`/звуков/карточек.
- Windows и реальные Диалоги не проверялись.
