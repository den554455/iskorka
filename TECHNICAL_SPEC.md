# «Искорка» — техническое задание и описание MVP

Версия документа: 1.0 · Дата: 2026-10-20 · Статус: MVP первой серии реализован и проверен локально; интеграция с Яндекс Диалогами **не проверялась**.

---

## 1. Цели и границы MVP

**Цель.** Голосовой навык-сериал для детей 4–8 лет: ребёнок дружит с лисёнком Искоркой, принимает решения и меняет свою Долину чудес. Удержание строится на сюжете и постоянных персонажах, а не на очках, таймерах и ежедневных сериях.

**В MVP входит**
- первая серия «Последнее семечко» (3–5 минут): знакомство с Искоркой и Тишей, выбор места для семечка (сад или ручей), последствие выбора, завершение;
- сохранение прогресса и решений на нашей стороне (SQLite), восстановление при повторном запуске;
- распознавание ответов по нескольким формулировкам, подсказки, мягкая обработка непонятных ответов;
- команды «Помощь», «Что ты умеешь», выход;
- защита от двойного начисления наград при повторных запросах;
- автоматические тесты.

**Не входит:** приложение, графика, регистрация, социальные функции, реклама, покупки, валюты, инвентарь, ежедневные награды, генеративный ИИ в репликах, аналитика поведения. Персонажи Пуговка и Кап в сценарии не появляются, так как не реализованы.

## 3. Требования платформы Яндекс Диалоги

### 3.1. Подтверждено по официальной документации

Источники: yandex.ru/dev/dialogs/alice/doc/ru — «Формат запроса», «SimpleUtterance», «Формат ответа», «Хранение состояния», «Требования к навыкам», «Размещение навыка на своём сервере», «Протокол работы». Проверено 2026-10-20.

**Запрос**
- Диалоги шлют `POST` на Webhook URL (в консоли — блок «Backend»), тело — JSON, версия протокола `"1.0"`.
- Поля: `meta`, `request`, `session`, `state`, `version`.
- `request.type`: `SimpleUtterance`, `ButtonPressed`, `Show.Pull`. Нажатие кнопки без `payload` приходит как `SimpleUtterance` с текстом кнопки.
- `request.command` — нормализованный текст (нижний регистр, без знаков препинания, числительные → числа); `request.original_utterance` — полный текст, максимум 1024 символа. Значение `ping` в `original_utterance` означает проверочный запрос Диалогов.
- При первом обращении в сессии (`session.new = true`) остальные поля `request` приходят пустыми.
- `request.markup.dangerous_context` — признак «криминального подтекста» (самоубийство, ненависть, угрозы); бывает только `true`.
- `session`: `session_id` (≤64), `message_id` (растёт с каждым запросом), `skill_id`, `new`, `application.application_id` (≤64; уникален для пары «приложение — навык»), `user.user_id` (только у авторизованных). Поле `session.user_id` **объявлено неподдерживаемым** — вместо него `session.application.application_id`.
- Для разных приложений (Android и iOS) выдаются разные идентификаторы, даже при одном аккаунте.

**Ответ**
- Обязательны: `response.text` (≤1024 символов), `response.end_session`, `version`.
- Необязательны: `tts` (≤1024), `buttons[]` (`title` ≤64; без `url` нажатие отправляет текст кнопки; `hide`), `card`, `directives`.
- Время ответа — 4,5 секунды, иначе сессия завершается, а Алиса сообщает, что навык не отвечает.

**Состояние**
- Хранилище Диалогов нужно включить в настройках навыка («Использовать хранилище данных в навыке»). `session_state` — внутри сессии, `user_state_update` — между сессиями **только для авторизованных**, `application_state` — для экземпляра приложения. Лимит каждого объекта — 1 КБ. Раздел описан как работающий в тестовом режиме, протокол может измениться.
- Историю неавторизованных пользователей документация рекомендует хранить на своём сервере.

**Модерация и содержание**
- Навык должен поддерживать команды «Помощь» и «Что ты умеешь». Для игровых навыков помощь содержит правила игры.
- Допускается не более 1 ошибки сервера на 10 обращений.
- Приветствие должно делать понятным, что можно сказать дальше.
- Навык должен соответствовать возрастной категории; если он доступен несовершеннолетним, нужно предусмотреть доступ только к допустимой информации.
- Реклама в ответах запрещена. Тексты — грамотные, без грубой лексики.
- После публикации навык периодически проверяется; если он не отвечает несколько часов, его отключают.
- Название навыка — не менее двух и не более пяти слов (не считая предлогов, союзов, частиц); нельзя «Яндекс», «Алиса», «Станция»; нельзя превосходные степени и «кликбейт». Дополнительные активационные имена — от двух до четырёх слов.
- Тестирование: вкладка «Тестирование» в консоли разработчика (`dialogs.yandex.ru/developer`).

### 3.2. Проектные решения (наши, не требования платформы)

| Решение | Обоснование |
|---------|-------------|
| Ключ игрока = `session.application.application_id`, запасной — `session.user_id` | Есть у всех, в том числе неавторизованных; не требует аккаунта |
| В БД хранится `HMAC-SHA256(pepper, id)`, а не сам идентификатор | Минимизация данных; утечка БД не раскрывает идентификаторы платформы |
| Состояние не дублируется в `session_state`/`user_state_update`/`application_state` | Единый источник правды — наша БД; нет лимита 1 КБ |
| Ответ только `text` (без `tts`, карточек) | Достаточно для MVP; `tts` с ударениями — позже |
| Кнопки без `payload` | Нажатие приходит обычной репликой, поведение подтверждено документацией |
| Невалидный запрос → HTTP 400 JSON, не голосовой ответ | Платформа такие запросы не шлёт |
| Любая внутренняя ошибка → HTTP 200 и «Ой, у Искорки запутались лапки…» | Ребёнок не слышит технических деталей; Диалоги не считают это ошибкой сервера |
| `ping` отвечается без создания профиля | Проверочные запросы не должны засорять БД |
| `dangerous_context` → нейтральный ответ «расскажи взрослому» и продолжение сказки | Не обрабатываем реплику как ответ на вопрос |

### 3.3. Предположения, которые нужно проверить (см. также раздел 10)

1. Повторная доставка запроса при тайм-ауте идёт с теми же `session_id` и `message_id`. Идемпотентность построена на этом.
2. `message_id` не уменьшается внутри сессии.
3. Один и тот же `application_id` сохраняется между запусками на одной колонке/в одном приложении.
4. Платформа не подписывает запросы; защита — необязательный секрет в пути URL.
5. Команды «Помощь» / «Что ты умеешь» доходят до навыка, а не перехватываются платформой.
6. Как именно обрабатывается `ButtonPressed` с `payload` — **не используется**, не проверялось.

## 4. Архитектура

```
Яндекс Диалоги ──HTTPS POST──▶ FastAPI (app/api/alice_webhook.py)
                                    │ валидация (pydantic), идентификатор, ping, ограничения
                                    ▼
                         GameService (app/service.py)
                          один ход = одна транзакция + замок
                            │                    │
                            ▼                    ▼
                   Engine (app/game)       Repository (app/db)
                   чистая логика           SQLite через SQLAlchemy
                   читает episodes.json    UNIQUE + ON CONFLICT DO NOTHING
```

Принципы:
- **Движок не знает про Алису и БД.** Вход: снимок состояния + реплика. Выход: `TurnResult` (текст, кнопки, новый узел, решение, награды).
- **Нет случайности.** Вариант фразы выбирается по номеру хода (`turn % число_вариантов`). Любой ответ воспроизводим и проверяем тестами.
- **Сценарий — данные.** `app/content/episodes.json` валидируется при старте; некорректный сценарий не даёт приложению запуститься.
- **Один ход — одна транзакция.** Решение, награда, новый узел и «последний ответ» сохраняются вместе или не сохраняются.

## 5. Игровой цикл

### Состояния

| Состояние | Роль | Хранится? |
|-----------|------|-----------|
| `NEW_GAME` | Начало игры. Любая реплика → приветствие | да (до первого хода) |
| `INTRO` | Знакомство, вопрос «Ты поможешь мне?» | да |
| `SEED_FOUND` | Находка семечка, знакомство с Тишей. Сразу переходит в `CHOOSE_PLACE` | нет (проходной) |
| `LISTEN` | Исследование находки: «послушаем семечко?» → `LISTEN_YES` / `LISTEN_NO` → `RIDDLE` | да |
| `RIDDLE` | Загадка Тиши (ответ «дерево»). Верно → `RIDDLE_OK`; после 3 неудач → `RIDDLE_REVEAL` (Тиша сам называет ответ). Дальше `WALK` → `CHOOSE_PLACE` | да |
| `WALK` | Проходной: прогулка по долине, описание сада и ручья | нет |
| `CHOOSE_PLACE` | Выбор места: сад / ручей | да |
| `GARDEN_SCENE`, `STREAM_SCENE` | Последствие выбора, награда. Сразу → `FINALE` | нет (проходные) |
| `FINALE` | Завершение серии, сессия закрывается; сохраняется как `EPISODE_COMPLETE` | нет |
| `EPISODE_COMPLETE` | Серия пройдена. При запуске: итог выбора + «послушать ещё раз?» | да |
| `RECAP`, `BYE`, `INTRO_NO` | Концовки сессии без изменения состояния | нет |

**HELP и EXIT — не сохраняемые состояния, а действия:** после помощи нужно вернуться к тому же вопросу, после выхода — продолжить с того же места. Поэтому они не меняют сохранённый узел.

### Порядок разбора реплики

1. `dangerous_context` → нейтральный ответ, состояние не меняется.
2. Выход («хватит», «стоп», «пока», …) → прощание, `end_session = true`, прогресс сохранён.
3. Первый ход (`NEW_GAME`) → приветствие.
4. «Что ты умеешь» / «Помощь» → текст + повтор текущего вопроса.
5. Новая сессия при существующем профиле → «С возвращением» + краткий пересказ + вопрос.
6. Подсказка («подскажи», «не знаю») → подсказка; не считается неудачей.
7. Ожидаемый ответ узла (да/нет, сад/ручей, …) → переход.
8. «Повтори» → пересказ + вопрос.
9. Иначе — непонятный ответ.

### Непонятный ответ

| Подряд неудач | Реакция |
|---------------|---------|
| 1 | Мягко повторить вопрос другими словами |
| 2 | Подсказка с точными словами для ответа и кнопками |
| 3–4 | Упрощённая помощь. На выборе места — вопрос «в саду? да/нет» (да = сад, нет = ручей). В `INTRO` — сюжет идёт дальше сам |
| 5 | Мягкое прощание без решения и награды; прогресс сохранён, при следующем запуске ребёнок вернётся к тому же вопросу |

Не более двух уточнений до упрощённой помощи. Ребёнок никогда не застревает: можно ответить «да», нажать кнопку, сказать «хватит».

## 6. Сценарий серии «Последнее семечко»

Все реплики — в `app/content/episodes.json`, по три варианта для ключевых реплик.

1. **Приветствие.** Искорка представляется, говорит о погасших ветвях Великого дерева, просит помочь («Скажи „да“»).
2. **Находка.** В корнях светится семечко; прилетает совёнок Тиша (знакомство, флаг `tisha`); «Это последнее волшебное семечко».
3. **Исследование находки** (`LISTEN`). «Приложим семечко к ушку, послушаем?» Да → семечко поёт; нет → Искорка греет его в лапках. Оба ответа ведут дальше, непонятный ответ сюжет не блокирует.
4. **Загадка Тиши** (`RIDDLE`). «У меня есть корни, но я не бегаю…» — ответ «дерево» (принимаются и дуб, ёлка и т. п.). Неверный ответ — мягкая подсказка без оценок; на третьей неудаче Тиша сам называет ответ, и сюжет идёт дальше. Ответ связывает сюжет: Великое дерево тоже было семечком.
5. **Прогулка** (`WALK`). Искорка и Тиша обходят долину: сад (тепло, пчёлы) и ручей (прохлада, поющая вода) — ребёнок выбирает осознанно.
6. **Выбор.** «Где посадим семечко: в саду или у ручья?» Кнопки «В саду» / «У ручья».
7. **Последствие.**
   - Сад → светящийся цветок, разблокирован элемент мира `garden_flower`.
   - Ручей → блестящий росток, вода искрится, `stream_sprout`.
8. **Финал.** Ветви дерева засветились ярче; у дерева есть тайна, которую разгадаем в следующий раз. Сессия закрывается.
9. **Повторный запуск.** Искорка рассказывает, что выросло, и предлагает послушать, как это было. Новая серия «пока готовится» — без давления и сроков.

Принципы реплик: короткие предложения, никаких угроз и чувства вины, личных данных не просят, правильных и неправильных ответов нет, выйти можно всегда.

**Расхождение с целью по длительности.** Целевая продолжительность — 3–5 минут. Замер объёма текста: прохождение без подсказок — около 2 000 знаков (2 016 для сада, 2 002 для ручья; до расширения было около 900, затем 1 170). При типичной скорости речи 12–15 знаков в секунду это примерно 2,2–2,8 минуты озвучки (оценка по объёму, а не замер). Это чистая речь Алисы: к ней добавляются ответы ребёнка (четыре реплики на пути без ошибок) и паузы, поэтому реальная сессия вероятно укладывается в 3–5 минут, но **это не измерено**. Чистая речь пока ниже 3 минут. Если замер на устройстве покажет меньше — дописать ещё одну сцену или второй выбор. Реальную длительность нужно мерить на устройстве.

## 7. Схема данных

| Таблица | Назначение | Ключевые ограничения |
|---------|-----------|----------------------|
| `profiles` | Профиль и состояние диалога: `player_key`, `episode_id`, `node`, `unclear_count`, `turn`, `last_session_id`, `last_message_id`, `last_response` | `UNIQUE(player_key)` |
| `decisions` | Сюжетные решения | `UNIQUE(profile_id, episode_id, key)` — первое решение не перезаписывается; FK → `profiles` |
| `world_items` | Открытые элементы мира (награды) | `UNIQUE(profile_id, item_key)`; FK |
| `character_meetings` | Флаги знакомства с персонажами | `UNIQUE(profile_id, character_key)`; FK |
| `episode_progress` | Прогресс серий, `completed_at` | `UNIQUE(profile_id, episode_id)`; FK |

- Внешние ключи включены (`PRAGMA foreign_keys=ON`), `ON DELETE CASCADE`.
- Отдельные индексы не нужны: все запросы идут по `player_key` и `profile_id`, их покрывают UNIQUE-индексы.
- Схема создаётся автоматически при запуске (`create_all`), файл БД и каталог — тоже.
- **Не хранится:** имя, телефон, голосовые записи, расшифровки речи, исходный идентификатор платформы. `last_response` — это наш собственный ответ, а не речь ребёнка.
- Миграций в MVP нет. При изменении схемы: удалить `data/iskorka.db` (на этапе разработки) или добавить Alembic.

### Защита от двойных наград

1. `(session_id, message_id)` совпал с последним обработанным или меньше → возвращается сохранённый ответ, состояние не меняется.
2. Награды и решения вставляются `INSERT … ON CONFLICT DO NOTHING` по UNIQUE-ключу.
3. Если решение уже сохранено, движок ведёт по сохранённой ветке, а не по новой реплике.
4. Весь ход — в одной транзакции; при ошибке откатывается всё.

## 8. Протокол webhook

`POST /alice` (или `POST /alice/<WEBHOOK_SECRET>`, если секрет задан). `GET /health` — проверка живости.

| Ситуация | Ответ |
|----------|-------|
| Корректный запрос | 200, `{"response": {"text", "end_session", "buttons"?}, "version": "1.0"}` |
| Тело > `MAX_BODY_BYTES` (64 КБ) | 413 |
| Невалидный JSON, не объект, нет `request`/`session`/`session_id`, поля длиннее лимитов платформы | 400 `{"error": "bad_request"}` |
| Лишние поля | игнорируются |
| `ping` | 200, короткий ответ, профиль не создаётся |
| Нет идентификатора приложения | 200, вежливое сообщение, `end_session = true` |
| Любое исключение внутри обработки | 200, «Ой, у Искорки запутались лапки…», в логах только имя класса исключения |

Кнопки: `title ≤ 64`, `hide: true`; при `end_session = true` кнопок нет.

## 9. Безопасность

| Мера | Как реализована |
|------|-----------------|
| Нет генеративного ИИ | Все реплики заранее написаны; выбор по номеру хода |
| Нет личных данных | Не спрашиваем; идентификатор хранится хэшем |
| Нет записей речи | Тексты реплик ребёнка в БД и логи не попадают (проверено тестами) |
| Проверка на сервере | Все переходы и награды — в движке/БД |
| Ограничения входа | 64 КБ на тело, лимиты длины полей по документации Яндекса, нормализация реплики до 200 символов |
| Ошибки | Traceback и внутренние детали ребёнку не передаются (тест) |
| Мягкие реплики | Нет стыда, давления, «потеряешь прогресс», ежедневных серий |
| Понятный выход | «Хватит», «стоп», «пока» работают на любом шаге |
| Логи | Без идентификаторов и реплик (тест `caplog`) |
| Секреты | `.env` в `.gitignore`; соль для хэша — `PLAYER_KEY_PEPPER` |

**Риски, которые backend закрыть не может:** качество распознавания детской речи; поведение платформы (повторы, идентификаторы, перехват команд); юридические требования к обработке данных несовершеннолетних и их соблюдение при публикации; безопасность хостинга и канала (HTTPS, доступ к серверу); смена идентификатора при переустановке приложения.

Смена `PLAYER_KEY_PEPPER` после запуска «осиротит» все профили — хранить её надёжно.

## 11. Известные ограничения и план

**Ограничения MVP:** серия чистая озвучка около 2,2–2,8 минуты (цель 3–5 с учётом реплик ребёнка не измерена); в серии один значимый выбор (сад/ручей), две вопроса-согласия без последствий и одна загадка; одна серия; профиль привязан к устройству/приложению; один процесс; без миграций БД; без `tts` и звуков; кнопки без `payload`; нет защиты от подделки запросов, кроме необязательного секрета в URL; распознавание словарное, без учёта опечаток распознавателя.

**Следующие версии**
1. Тест в консоли Диалогов, разбор логов, правки по модерации.
2. Привязка прогресса к `session.user.user_id` для авторизованных пользователей (одинаков на всех устройствах) с переносом профиля при первом входе.
3. `tts` с ударениями и звуки из библиотеки Алисы.
4. Серия 2 (раскрытие тайны дерева, Пуговка, Кап); уровень мира «Долина чудес» как сводка решений.
5. Alembic-миграции; PostgreSQL при росте нагрузки.
6. Отдельная панель сброса профиля по просьбе родителя («Алиса, начни сначала»).
